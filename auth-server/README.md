# Telegram Login - подготовленная защищённая серверная часть

Это **заготовка, не включённая в публичный сайт**. Раздел `auth-server` может быть корневой папкой отдельного бесплатного тестового проекта Vercel (Node.js >=20). Пока адрес и секреты не настроены, запросы не выполняют вход.

Для запуска необходимо вручную создать/разрешить проект и указать **секретные переменные только в настройках хостинга**, не в GitHub и не в чате:

- `TG_CLIENT_SECRET` - секрет Telegram Login из BotFather.
- `TG_SESSION_SECRET` - случайный криптографически стойкий ключ, не меньше 32 символов.
- `AUTH_BASE_URL` - публичный HTTPS-адрес будущего сервера входа, без конечного слеша.
- `SITE_RETURN_URL` - `https://numerologia-online.github.io/numerologia-online/`.

В BotFather > Login Widget > Redirect URIs добавить **точно**: `<AUTH_BASE_URL>/api/callback`.

Маршруты:
- `GET /api/start` - стандартный OIDC Authorization Code + PKCE, переход без попапа.
- `GET /api/callback` - подтверждает state, обменивает code с Telegram на сервере, проверяет RS256 и возвращает кратковременный подписанный ticket в URL-фрагменте главной страницы.
- `GET /api/session` с заголовком `Authorization: Bearer <ticket>` - проверяет подпись и возвращает минимум данных (Telegram ID, имя).

Не сохраняем PDF, дату рождения, расчёты, номера телефонов. Код не открывает платные уроки. Для постоянных коммерческих аккаунтов позднее понадобится безопасная сессия и хранилище записей о доступе, а также платформа, разрешающая коммерческое применение.

**Важно:** ничего не переключать на новый вход до реального развёртывания и проверки. Vercel отказал в автоматическом создании проекта: HTTP 403.
