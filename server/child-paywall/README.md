# Детский разбор: подготовка платного доступа на REG.RU (НЕ развёрнуто)

**Модель:** одна покупка `child_full_v1` за 490 ₽ открывает один `child_id` только внутри подтверждённого `account_id`. Другая дата, другой ребёнок или другой аккаунт не получают доступ автоматически. Одинаковые даты у разных детей допускаются, потому что у каждого отдельный UUID.

**Бесплатно:** только «Характер и темперамент» на матрице. «День ребёнка» пока остаётся отдельным бесплатным разделом. Остальные 20 глав и весь PDF требуют покупки. На GitHub Pages сейчас действует только визуальная блокировка; её нельзя считать защитой контента.

## Что подготовлено
- `schema.sql`: аккаунты, дети (UUID + дата), платежи и права (entitlements).
- `public/api/child-access.php`: пример строгой проверки подписанного Telegram Mini App initData, владельца ребёнка, даты и подтверждённого платежа. Без сервера и подписанных данных выдаётся только preview.
- `private/grant-paid-purchase.php`: выдача права ТОЛЬКО после подтверждения оплаты провайдером. Сам по себе этот файл ничего не активирует.
- Секреты, настоящее подключение MySQL и платёжный webhook намеренно НЕ добавлены в репозиторий.

## Перед настоящими продажами ОБЯЗАТЕЛЬНО
1. Развернуть PHP и MySQL на REG.RU и выполнить `schema.sql`. Папку `private/` положить ВНЕ доступного из интернета каталога. Создать `private/config.local.php` непосредственно на хостинге, включая `bot_token`, `mysql_dsn`, `mysql_user`, `mysql_password`, `site_origin`.
2. Связать постоянный аккаунт сайта (Telegram/VK/email) с `user_accounts`. Этот прототип проверяет только Telegram Mini App; обычный браузер требует дополнительно проверенной серверной сессии, а не переданного клиентом `user_id`.
3. Сделать серверное создание `child_profiles` с UUID, привязанным к авторизованному аккаунту. Определять ребёнка именно по `child_id`, НЕ только по дате. В чекауте фиксировать тот же `child_id`.
4. Настроить провайдера оплаты: сервер проверяет подпись webhook или запрашивает состояние платежа у провайдера, фиксирует уникальный `provider_payment_id` и только тогда вызывает `grantVerifiedChildPurchase`. «Оплачено» от браузера никогда не принимается.
5. ПЕРЕНЕСТИ все платные `child/data/matrix/sections/energy-*.json` (кроме отдельно выгруженного публичного раздела `character`) и кармические программы из опубликованного GitHub Pages в закрытое хранилище вне webroot на REG.RU. Сейчас в каждом `energy-N.json` находятся сразу ВСЕ темы, поэтому их можно прочитать по прямой ссылке даже с замком на сайте.
6. Организовать защищённый `GET /api/child-reading` и `GET /api/child-report`: сервер сначала проверяет аккаунт, `child_id`, дату рождения и entitlement, затем выдаёт текст только запрошенной разрешённой главы и генерирует/отдаёт PDF. Для бесплатной главы выдавать только публичное `character`, без других секций. Клиентский `child-report-pdf.js` нельзя оставлять источником платных текстов.
7. Только после успешных тестов HTTP 401/403 для гостей, владельца другой покупки, другой даты, отозванного платежа и прямых URL банка переключить фронтенд на реальные API и убрать тестовые надписи.
8. Для двойни нужны отдельные `child_id` и записи покупки. Форма выбора ребёнка будет добавлена вместе с постоянным аккаунтом; одного поля даты для жёсткой привязки недостаточно.

**Статус сейчас:** схема БД и эталон строгой проверки готовы в GitHub, но не установлены на REG.RU. Фронтенд работает в fail-closed режиме и не обещает фактический доступ после оплаты до подключения серверной части. Нельзя начинать сбор реальных платежей до выполнения пунктов выше.
