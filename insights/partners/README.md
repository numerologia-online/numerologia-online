# Партнёрская аналитика — исходный код в main

Статус: код сохранён в главной ветке GitHub. На REG.RU не опубликован; схема в MySQL не применена. Партнёрская аналитика не включена на действующем сайте.

Эта подсистема **использует существующие** `numi_accounts` и `numi_orders` и не создаёт второй кабинет покупателей или новый реестр платежей. Для самой партнёрской атрибуции предусмотрены четыре отдельные служебные таблицы в `schema.sql`; это не таблицы покупателей и не дублирующие заказы.

## Состав
- `numi-partners.php` — серверный API: переходы по ссылкам, закрепление партнёра за существующим аккаунтом, отчёт только по проверенным заказам.
- `schema.sql` — предполагаемая схема служебной аналитики; **не применять** без бэкапа и проверки действующей базы.
- `index.html`, `partners.js` — интерфейс владельца.
- `referral-client.js` — необязательная клиентская атрибуция после согласия на аналитику.
- `tests/partners.mysql.php` — интеграционные тесты для отдельной тестовой MySQL.

Старые `deploy-reg.py`, автопубликационные workflow и `referral-bootstrap.html` намеренно не перенесены: они содержали привязку к старому окружению / процедурам публикации. Актуальная настройка публикации должна выполняться отдельно после ревизии.

## Важно перед запуском
1. Проверить точный домен, API, сессии и права владельца; в PHP указан основной домен.
2. Проверить на отдельной MySQL все тесты, индексы, реальную готовность схемы.
3. Исправить обнаруженные проблемы, выполнить security review, проверить согласие на cookie и документацию.
4. Убедиться, что `numi_orders` действительно получает подтверждённые платежи от будущей ЮKassa: сейчас платежная интеграция не доказана.
5. Опубликовать на REG.RU только после отдельного разрешения владельца; изменения файлов GitHub **не** публикуются автоматически.

Данный перенос — консолидация исходников. Он **не является** подтверждением готовности аналитики или платежей к эксплуатации.
