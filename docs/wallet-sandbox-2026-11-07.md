# Единый рублёвый баланс: тестовая разработка (7 ноября 2026)

Статус: исходный код в GitHub main. **НЕ опубликовано на REG.RU, сквозная проверка не проведена, настоящие деньги не включены.**

## Реализовано в исходниках
- Единый персональный рублёвый баланс (копейки в MySQL, отдельная запись для каждого account_id).
- Пополнение 100 / 300 / 500 ₽ через **существующую тестовую** ЮKassa.
- Баланс увеличивается исключительно после повторного запроса подтверждённого тестового платежа у ЮKassa, проверяется сумма, идентификатор пополнения, валюта и флаг test.
- Журнал операций, уникальные ключи операций, транзакции и блокировки MySQL для защиты от повторного зачисления и списания.
- Одно нажатие для покупки готового вопроса Red Flag или «Да/нет»: сервер рассчитывает цену и выдаёт entitlement, результат открывается в интерфейсе магазина; «Сохранённое» остаётся доступно.
- Баланс показан в действующем интерфейсе личного кабинета для тестового пользователя.
- Ранее отдельная разовая оплата после подтверждения теперь автоматически открывает материал при единственном купленном товаре.

## Защита от включения раньше времени
Новый API закрыт без действующей авторизации и конфигурации магазина, а также без отдельного private-флага store_wallet_test_enabled === true. Только владелец или allowlist store_test_account_ids; самоподключение через браузер запрещено. Действующий адаптер платежей требует test_-ключ и test=true. Реальные платежи не включать.
Существующие схемы numi_orders/numi_entitlements не удаляются и не переопределяются. Новые wallet-таблицы создаются добавочно.

## Прежде чем публиковать
1. На REG.RU сравнить оригиналы перечисленных 5 файлов и сделать бэкапы; сохранить серверные изменения, которых нет в GitHub. Иначе не публиковать.
2. Проверить синтаксис PHP и браузерной логики, схему на отдельной тестовой базе MySQL и совместимость с действующим schema/order service.
3. Установить 6 файлов, включить тестовый флаг **только** для заданного тестового аккаунта, без реальных платежей.
4. Проверить пополнение → подтверждение ЮKassa → баланс → вопрос → ответ открыт немедленно → «Сохранённое» → повторный вход; параллельные повторные запросы и баланс 0.
5. Проверить обработку отказа, возврата, частичного возврата, потерянных ответов ЮKassa и повторной доставки уведомлений. Пока возвраты кошелька не поддержаны; не включать настоящий приём предоплат.
6. Согласовать правовой режим авансов, фискализацию, возврат остатка и условия оферты до любых реальных пополнений.

**Не изменять** Telegram, бот, CRON, действующие ключи, настройки ЮKassa и реальные покупки во время тестовой публикации.
