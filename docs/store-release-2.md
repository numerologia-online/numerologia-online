# Магазин: комплект №2

Продолжение f168651. Только main. Никакие реальные списания не поддерживаются:
адаптер отклоняет live-ключи и каждый ответ провайдера обязан содержать test=true.

## Перенос одним архивом

Архив содержит код, приватные копии разрешённых исходников, проверочные хеши и
один установщик install-store.php. Он НЕ содержит ключей ЮKassa, GitHub-токенов,
паролей, пользователей, покупок, дампа базы или настроек CRON.

Архив с авторскими материалами нельзя распаковывать в www, выкладывать в публичный
GitHub, на GitHub Pages или в другую публичную папку. На REG.RU его размещают в
отдельной папке внутри ~/private, распаковывают там и запускают PHP CLI из этой
папки. Массовая ручная загрузка файлов не нужна.

Проверка без изменений:

```sh
php install-store.php --home=/ПРОВЕРЕННЫЙ/ДОМАШНИЙ/КАТАЛОГ --site=/ПРОВЕРЕННЫЙ/КОРЕНЬ/САЙТА
```

Только после успешной проверки тот же вызов с параметрами:

```sh
php install-store.php --home=/ПРОВЕРЕННЫЙ/ДОМАШНИЙ/КАТАЛОГ --site=/ПРОВЕРЕННЫЙ/КОРЕНЬ/САЙТА --apply --verify-origin=https://xn----8sbhhqijddjgdebdz2c2o.xn--p1ai
```

Установщик проверяет каждый старый файл относительно f168651 и каждый входящий файл
по SHA256; уже совпадающие новые версии пропускает. При любом неизвестном
изменении, отсутствии ожидаемого старого файла или неожиданном существующем новом
файле весь перенос останавливается до записи. Копирование текущего сайта поверх
известной базы не разрешено. Если действующая версия не соответствует f168651,
сначала нужно получить действующие исходники, проверить расхождения и подготовить
отдельную сверенную базу. Автоматического слияния конфликтов нет.

Перед заменами сохраняются и сверяются все затрагиваемые старые файлы в отдельной
папке ~/private/numi-store-backup-*. Новые файлы сначала подготавливаются рядом с
назначением, затем заменяются атомарно. Главная устанавливается последней.
Проверяются API health, гостевая session и новый cart_quote. При сбое установщик
возвращает установленным файлам старые версии; обнаруженные сторонние изменения
не перезаписывает. База, Telegram, рассылки и действующие задания CRON не меняются.

Старый deploy-store.py на шесть файлов отключён: он не мог доставить зависимости
второго комплекта. GitHub Actions не используются.

## ЮKassa и подписки

Существующая приватная конфигурация предусмотренного адаптера:
~/private/numi-wallet-test-20261106/config.local.php. В этом комплекте её нет и
она не создаётся/не перезаписывается. До включения теста нужно сверить фактический
путь и поля действующего подключения, без копирования секретов в чат или GitHub.

Контракт адаптера: shop_id, secret_key с префиксом test_, store_test_enabled=true.
Тест допускается владельцу либо явно перечисленным account_id из
store_test_account_ids. Новых прав администратора тестовым аккаунтам не выдаётся.
Список store_ready_products больше не включает продажи: готовность проверяется
по конкретному материалу и подписи каждого исходника непосредственно на сервере.

Для рекуррентного теста отдельно требуются store_recurring_test_enabled=true,
галочка покупателя, подтверждённый payment_method.saved и непрозрачный ID метода
ЮKassa. Номера карт/CVC не сохраняются. Отключение автопродления сохраняет текущий
оплаченный период. Даты продления добавляются к оставшемуся сроку, а не заменяют его.

Закрытый store-renew.php — обработчик рекуррентного теста через тот же платёжный
адаптер. Он не установлен в существующий CRON. При тестировании запускается из
CLI вручную; для настоящей регулярной обработки позднее потребуется отдельный
проверенный вызов планировщика. Изменять действующий утренний CRON для этого нельзя.
При ошибке сети повторяется тот же checkout/idempotency key; спустя 23 часа
неопределённый платёж требует сверки, а не нового списания.

Webhook: /api/numi-account.php?notification=yookassa, события payment.succeeded,
payment.canceled, refund.succeeded. Содержимое уведомления не даёт доступ: статус,
сумма, валюта, metadata и test заново проверяются через API провайдера.
Любой подтверждённый возврат консервативно отзывает права всей корзины. Частичные
возвраты пока требуют ручной сверки отдельных позиций; реальные продажи остаются
запрещёнными до решения этой политики и проверки фискализации.

## Материалы

Тексты не сочинялись заново. Для жизни, совместимости, ребёнка и «Да или нет?»
использована закрытая версия исходников e37c5f4ba3b2d3dfc5b6a204f4d99be2246784a9.
На сервер попадают только предусмотренные файлы; браузер получает один купленный
результат, а не весь банк ответов. PDF собирается из повторно авторизованного
результата с существующим PDFMake. Открытие и скачивание проверяют срок и владельца.

Все 481 вопрос и 11 направлений остаются в каталоге. У незаполненного материала
или несовпадающего хеша покупка заблокирована. Момент закрыт независимо от наличия
текста. Детский разбор допускается только при полноте всех глав и соответствующего
кармического хвоста. Некоторые даты/вопросы поэтому намеренно недоступны.

Клубные ритуалы требуют даты рождения в существующем профиле для личного кода.
Школа использует канонический school_week; проверка владельца сохраняется отдельно,
покупатель школы не получает флаг владельца.

## Границы проверки

Локальные PHP/SQLite/DOM-тесты не заменяют проверку MySQL, почты регистрации,
реального ответа sandbox ЮKassa и доступности PDF с телефона на REG.RU.
Ни установка, ни сохранение main не означают прохождения этих серверных тестов.
Нужен сквозной тест отдельного разрешённого аккаунта: регистрация/вход, корзина,
оплата в sandbox, webhook/возврат из оплаты, повторный вход, материал/PDF, подписка,
продление, отмена и возврат. До него запуск продаж объявлять нельзя.
