# Публикация статей на REG.RU без GitHub Actions и Codex

**Статус: подготовлено в GitHub, НЕ установлено на REG.RU.**

Скрипт: `deploy/regru-content-pull.php`. Работает **только в PHP CLI** по расписанию хостинга; не допускает вызов через веб-браузер.

Что обновляет: `guide/index.html`, `guide/<slug>/index.html`, `guide/guide.css`, `guide/journal.css`. Не обновляет PHP, JavaScript, платные материалы, оформление кабинета, оплату, ботов, приватные тексты, базу данных.

## Однократная настройка на REG.RU

1. Подтвердить настоящий document root нового сайта и убедиться, что `guide/` — верный каталог статей.
2. Положить только `deploy/regru-content-pull.php` **в приватную папку вне document root**. Не переписывать действующие файлы сайта.
3. Создать другую приватную папку для `content-sync-state.json` и lock-файла, с доступом на запись от PHP CLI.
4. Задать для PHP CLI окружение `NUMI_CONTENT_SITE_ROOT` и `NUMI_CONTENT_STATE_DIR` с точными абсолютными путями. Запустить вручную сначала с `NUMI_CONTENT_DRY_RUN=1` и изучить конфликты. Существующие несовпадающие статьи скрипт не перезаписывает, пока не завершена одноразовая сверка/подтверждение их текущей версии.
5. Для проверенного списка существующих страниц можно однократно записать в `content-sync-state.json` соответствия `{ "guide/slug/index.html": "sha256_действующего_файла" }` после сравнения и согласия на обновление. НЕ устанавливать baseline вслепую. Новые статьи могут появляться и без baseline.
6. Запустить в настоящем режиме один раз и проверить изменения в вебе. Только после успешной проверки добавить задание REG.RU Cron каждые ~10 минут (реальная частота зависит от тарифа).
7. Изменить на GitHub безопасную тестовую статью, убедиться, что на REG.RU она обновилась без GitHub Actions, Codex и ручной передачи файлов.
8. Если на сервере появилась ручная правка, скрипт фиксирует конфликт и не затирает её. История GitHub сохраняет версии. Скрипт ничего не удаляет.

Скрипт использует только публичный GitHub и не требует GitHub-токена. Не записывать приватные ключи или данные пользователей в репозиторий.

**Без шага однократной установки скрипт не запускается и ни одна статья автоматически не публикуется.**
