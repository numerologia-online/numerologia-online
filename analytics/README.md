# Нумерология онлайн — аналитика интересов (пилот)

**Статус:** код в main, публикация запускается workflow `numi-analytics-release.yml`. Реальную доступность и результат workflow нужно подтвердить отдельно.

## Подготовлено
- MySQL-таблица `analytics/schema.sql`: агрегированные суточные счётчики.
- PHP API `analytics/public/numi-analytics.php` (назначение `/api/numi-analytics.php`): POST события, GET статистика только после отдельного входа через email+пароль владельца (нельзя открыть обычной Telegram-сессией).
- `moment/analytics.js`: лёгкий счётчик без куки, localStorage, IP, идентификаторов, дат рождения и полных поисковых запросов. Отключается при Global Privacy Control или Do Not Track.
- `analytics/admin/`: закрытая панель для владельца, периоды 1/7/30/90 дней.
- Подключены просмотры страниц/тем/вопросов и факт использования поиска в каталогах 300 и 100 вопросов.
- Поддерживаются ссылки из бота с параметром `utm_campaign=morning_20261101`; в базе хранится только эта обезличенная метка, не Telegram ID.

**Важно:** это счётчики действий, НЕ уникальных пользователей и не индивидуальный профиль человека. Никаких сырых поисковых запросов и свободного текста.

## Перед запуском на REG.RU
1. Резервировать рабочую базу; новая таблица `numi_analytics_daily` создаётся автоматически **только после первого успешного входа владельца с паролем**. Исходный шаблон схемы также находится в `analytics/schema.sql`.
2. Убедиться, что на сервере установлена действующая `account-service/private/core.php` и подключается `db.php`.
3. Используется существующая проверка `naTestOwner` по хешу подтверждённого email и дополнительная отдельная аналитическая сессия после успешного ввода пароля. В GitHub нет пароля и идентификатора владельца.
4. Публикация через workflow устанавливает API как `/api/numi-analytics.php`, панель как `/analytics/`, а общий JS как `/moment/analytics.js`, с резервными копиями и проверкой HTTP.
5. Только затем публиковать обновлённые `/moment/index.html`, `/moment/moment.js`, `/moment/yes-no/index.html`, `/moment/yes-no/yes-no.js`.
6. Проверить анонимный POST, отсутствие записи идентификаторов, GET 403 без входа, GET 403 с обычной Telegram-сессией, GET 200 владельцу **после отдельного ввода пароля**.
7. Проверить переходы из бота `?utm_campaign=morning_20261101`, категории и вопросы, а также отсутствие влияния на остальные разделы.
8. Измерить скорость на телефоне и под нагрузкой; гарантировать, что при отказе аналитического API основная страница продолжает работать.
9. Обновить уведомление о конфиденциальности и проверить правовое основание аналитики в применимой юрисдикции **до** публичного запуска. Данный вариант не использует идентифицирующие cookies, но это не автоматически освобождает от требований к информированию и согласию.
10. При одобрении расширить сбор на остальные разделы сайта и на покупки, используя только подтверждённые сервером факты (не сигналы об оплате из браузера).

Если workflow не подтверждает успешное развёртывание, не считать аналитику включённой. Не создавать пароль/права администратора по догадкам.
