## Важные ограничения

- **Никаких реальных цифр до запуска и сбора данных нет.** Ранее совершённые действия не восстановить.
- «Скачать PDF» сейчас измеряется по нажатию кнопки. Это НЕ подтверждённый успешный файл.
- Нажатие «Поделиться» НЕ означает, что сообщение отправлено.
- «Сессии» - анонимные сессии посетителей, давших согласие, а не уникальные люди.
- Публичные события могут накручиваться: Origin и разрешённые имена событий снижают случайные ошибки, но не защищают от целенаправленной подмены. Потребуются лимиты запросов и сверка с Метрикой.
- Подтверждённые оплаты специально принимаются только через защищённый серверный `POST /api/server-event`, никогда из браузера. Пока отправка подтверждений из платёжного обработчика не подключена, выручку показывать как реальные деньги нельзя.
- Бот пока не отправляет события. Подключать это отдельно после стабилизации действующих рассылок.
- Нельзя использовать этот кабинет как учётную систему заказов или основу для финансовой отчётности без сверки платежей.
- До включения счётчика на работающем сайте проверить уведомление о статистике, политику конфиденциальности, корректность согласия и требований применимого законодательства.

## Следующие шаги для подключения (можно делать с iPhone)

1. В Cloudflare создать **новую** D1 базу с названием `numerologia-owner-analytics`. Лучше хранить в регионе EU, если это подходит юридическим требованиям проекта. Не трогать существующие базы бота.
2. Развернуть SQL из `analytics/worker/schema.sql` на новой D1. Это новая таблица, работающий бот не затрагивается.
3. В `analytics/worker/wrangler.jsonc` заменить `REPLACE_WITH_REAL_D1_ID` на ID созданной базы.
4. Создать **отдельный** Worker `numerologia-owner-analytics` из GitHub: использовать корневую папку `analytics/worker` и соответствующую ветку. Нельзя перезаписывать Worker `numerologia-online-bot`. Cloudflare поддерживает подключение Git-репозитория к Workers Builds.
5. Установить в настройках этого Worker секреты: `ADMIN_TOKEN` и `BOT_INGEST_TOKEN`. Это **разные**, случайные строки длиной от 32 символов. НИКОГДА не добавлять их в GitHub, не отправлять в чат и не помещать в клиентский JavaScript.
6. Проверить `GET /health`, затем авторизованный `GET /api/overview?days=30`, убедиться, что пустая база показывает честные нули.
7. В скриптах главной страницы и `/pro/` прописать точный URL нового Worker в атрибут `data-endpoint` у `analytics/tracker.js` и проверить согласие посетителей, события и доступность сайта. Всё делать в ветке и только после успешных тестов согласовывать объединение с main.
8. Отдельным изменением добавить server-to-server события из текущего Telegram Worker (запуск, нажатия). Ещё отдельным - подтверждённые оплаты из REG.RU/PHP с уникальным `event_id` для защиты от двойного подсчёта.
9. По желанию подключить Яндекс Метрику отдельно для SEO-запросов, Вебвизора и сверки источников. Этот кабинет не заменяет Метрику.

### Команды для разработчика с терминалом (не обязательно делать пользователю с телефона)

В папке `analytics/worker` после создания D1 и замены ID:

```sh
npx wrangler d1 execute numerologia-owner-analytics --remote --file=schema.sql
npx wrangler secret put ADMIN_TOKEN
npx wrangler secret put BOT_INGEST_TOKEN
npx wrangler deploy
```

## Схема сервера

- `POST /api/event` - разрешённые публичные события с GitHub Pages, только после согласия. Не принимает оплаты.
- `POST /api/server-event` - подтверждённые серверные события из нашего бота/платёжной системы, требует `Authorization: Bearer <BOT_INGEST_TOKEN>`.
- `GET /api/overview?days=7|30|90` - отчёт, требует `Authorization: Bearer <ADMIN_TOKEN>`.
- `GET /health` - ответ о доступности сервера, без частной статистики.

**Принцип:** никаких дат рождения, Telegram ID, персональных вопросов, переписок и IP-адресов в D1 событиях. Вопросы фиксируются по статическому ID и заголовку. Сессия - случайный ID только после согласия.

Сервер и кабинет нужно проверить отдельно на iPhone; оплата должна сверяться с подтверждением провайдера. Не включать фейковые показатели, не считать клики деньгами, не создавать публичную базу, не делать пароль частью URL. Согласовать с владелицей проекта перед публикацией.
