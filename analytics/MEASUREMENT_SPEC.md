# Сквозная коммерческая аналитика (проект)
Дата: 2026-10-18. Статус: черновик, НЕ опубликован. Основной сайт и Telegram Worker не изменяются.

## Цель
Один защищённый мобильный кабинет с реальными данными. Никаких демонстрационных чисел вместо фактических.

## Отчёты
1. Трафик: источники, UTM source/medium/campaign, каналы, страницы входа и возвращаемость.
2. SEO: запрос, показы, клики, поисковый CTR, позиция отдельно для Яндекса и Google.
3. Разделы: посещения, расчёты, каждое открытие вопроса Red Flag, отдельные уникальные сессии, пересылки, клики PDF.
4. Воронки: вход -> фактический показ предложения -> нажатие оплаты -> оформление -> проверенная оплата -> активация подписки.
5. Выручка: подтверждённые платежи, тариф, возвраты, повторные платежи и продления.
6. Атрибуция: какие продукты и вопросы приводят к покупке, разрезы по источникам и кампаниям.
7. Выгрузка CSV для разбора вместе с ассистентом.

## Определения
- Поисковый CTR = клики в поисковой выдаче / показы в выдаче; источник: Яндекс Вебмастер или Google Search Console.
- CTR кнопки = уникальные сессии с нажатием кнопки / уникальные сессии с фактическим показом этой кнопки.
- Пошаговая конверсия = доля сессий, прошедших следующий шаг после предыдущего, в корректном порядке.
- Оплаченные заказы можно считать только по подтверждениям платёжного провайдера, с защитой от двойных уведомлений.
- Клик «поделиться» НЕ означает доставку, а клик «скачать PDF» НЕ означает успешную загрузку.
- Нельзя делать «сквозной путь» просто делением любых оплат на любые посещения: заказ должен быть связан с реальным визитом.

## Источники
- Яндекс Метрика: поведение, цели, воронки, источники.
- Яндекс Вебмастер: запросы, показы, клики, CTR по Яндексу.
- Google Search Console: запросы, показы, клики, CTR по Google.
- Наша приватная статистика: отдельные вопросы, действия в боте и данные подтверждённых покупок.
- Платёжная система: реальное подтверждение операции, возвратов и продлений.

## Клиентские события после согласия
page_view, redflag_open, redflag_category_open, redflag_question_open, redflag_share_click, redflag_save_click, telegram_link_click, pdf_download, subscription_offer_view, subscription_cta_click, checkout_started.
Из них передаём только технический ID, название опубликованной кнопки/вопроса, раздел, случайный идентификатор сессии и обезличенные параметры источника.
НЕ отправлять даты рождения, текст ответа, переписку, Telegram ID или любые личные данные.

## Серверные события
bot_start, bot_button, bot_active, payment_success, subscription_activated, subscription_renewed, payment_refunded.
Оплаты и возвраты поступают исключительно с серверной проверки платёжного провайдера, а не из браузера.
Нужен собственный transaction ID для идемпотентного учёта каждого события.

## Между сайтом, ботом и оплатой
Для реальной связи «Яндекс -> страница -> бот -> платёж» требуется специальная проверяемая цепочка: визит -> подписанный deep-link -> проверенный вход Telegram -> ID заказа -> подтверждение провайдера. Это отдельный этап; нельзя объявлять его уже готовым.

## План безопасного запуска
1. Отдельная D1-база и Worker только для статистики; защищённый кабинет с телефона.
2. Юридически корректное согласие на аналитику, затем подключение счётчика к сайту.
3. Метрика и цели с проверкой на тестовых действиях.
4. Вебмастер и Search Console; данные о поисковом CTR в едином кабинете только после их действительного подключения.
5. Привязка подтверждённых оплат и подписок к данным платежной системы.
6. Сквозная связь сайта/бота/оплаты и контроль качества данных.
7. Развитие в отдельную панель для будущих тематических сайтов и ботов.

Запрещено демонстрировать выдуманные показатели, публиковать токены и изменять действующий бот или рассылку без согласования.
